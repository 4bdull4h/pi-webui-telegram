# C3 — منظومة التنبيهات: أصوات + إشعارات نظام + تشخيص الانقطاع

> النطاق: `public/app.js` · `public/index.html` · `public/styles.css` فقط.
> لم يُلمس `src/**` ولا `extensions/**`، ولم يُعَد تشغيل خادم الإنتاج (كل الاختبار على منفذ مؤقت **8793**، بيانات `/tmp`، بلا تيليجرام).
> منطق الموافقة والـWebSocket وأسماء الأحداث كما هي؛ أُضيفت مراقبة جانبية فقط.

## 1) محرّك الأصوات الموحّد `SoundBus`

WebAudio خالص، **بلا أي ملفات صوت**: كل نوع = «بصمة» من نغمات مولّدة (تردد/موجة/مدة/كسب/انزلاق).

| النوع | البصمة | التنفيذ |
|---|---|---|
| `approval` | نغمتان صاعدتان حادّتان (1046 → 1568) مكرّرتان **3 مرات** | 6 نغمات `square` — الأكثر إلحاحاً |
| `done` | ثلاثية صاعدة هادئة | 523 → 659 → 784 `sine` |
| `error` | نزول منخفض | 330 → 247 → 165 `sawtooth` مع انزلاق ترددي |
| `toolFail` | نقرتان قصيرتان منخفضتان | 220 / 196 `square` · مدة كل نغمة 70ms |
| `disconnected` | نبض منخفض متكرر | 196 `triangle` × **4** كل 260ms |
| `reconnected` | نغمة صاعدة ثم هادئة | 523→784 ثم 659→587 |
| `message` | نقرة خفيفة جداً | 1175 `sine` · 45ms · كسب 0.16 |
| `limit` | تحذيرية متوسطة | 880 → 660 `triangle` |

- `AudioContext` يُنشأ/يُستأنف عند **أول تفاعل** (`pointerdown`/`keydown` على مستوى المستند)، ومع كل تشغيل يُعاد
  `resume()`؛ إن بقي معلّقاً تُجدول **إعادة محاولة تلقائية** بعد 350ms بدل إسقاط التنبيه.
- `prefers-reduced-motion` **لا يلغي الصوت**؛ يوقف الحركات (نبض أيقونة الشريط، حركة دخول الحوارات) فقط عبر CSS.
- **كل إعدادات التنبيهات في مفتاح `localStorage` واحد**: `piweb.notify.settings` =
  `{ sound: bool, volume: 0..100, types: { <typeId>: bool } }` — يُقرأ عبر `readNotifySettings()` ويُكتب عبر
  `patchNotifySettings()`، ويُهاجَر تلقائياً مرة واحدة من مفاتيح C2/C3 القديمة
  (`pi.extUi.sound` · `pi.alert.volume` · `pi.alert.sound.<type>`) عند أول تحميل.
- زر «تجربة» لكل نوع في اللوحة يشغّل بصمته مباشرة.

## 2) إشعارات النظام

- طلب الصلاحية عند **أول تفاعل** فقط، مع **نافذة شرح مختصرة** قبل طلب المتصفح
  (`#notifyExplain`)، وتُسجَّل `pi.notify.explained` كي لا تتكرر.
- الأحداث التي تُطلق إشعار نظام: `approval` (دائماً، `tag = "approval:<id>"`)، `done` (دائماً حتى لو كانت
  الصفحة مرئية)، `error`، `disconnected`، `reconnected` (+ `limit` عند 90% من أي حد).
- جسم الإشعار موحّد عبر `alertBody()`: **الحالة · مدة المهمة · الوكيل/النموذج · أول 80 حرفاً** من آخر رد أو نص الخطأ.
- `requireInteraction: true` للموافقة والانقطاع (وللخطأ). النقر ينفّذ `window.focus()` ثم يفتح حوار الموافقة
  أو يمرّر إلى الرسالة المعنية (`scrollToBottom`).
- عند رفض الصلاحية يظهر شريط `#notifyBar`: «🔔 الإشعارات معطّلة — فعّلها من إعدادات المتصفح» + زر «إعادة الطلب»
  + زر إغلاق، ونقطة حمراء على زر 🔔 في الشريط العلوي.

## 3) مراقبة الاتصال وتشخيص السبب

- نبضة كل **15 ثانية**: `fetch('/health', {cache:'no-store'})` بمهلة **5 ثوانٍ** (`AbortController`).
  **فشلان متتاليان ⇒ «منقطع»**.
- تصنيف السبب (`classifyClose`):

| السبب | الشرط | النص المعروض |
|---|---|---|
| `server-restart` | رمز إغلاق 1000/1001/1012/1013 | «الخادم يُعاد تشغيله … سنعيد الاتصال تلقائياً» |
| `auth` | 1008 / 4401 / 4403 | «فشل التحقق من الجلسة — رمز الدخول غير صالح أو منتهٍ» |
| `network` | `navigator.onLine === false` | «لا يوجد اتصال بالشبكة … عند عودة الشبكة» |
| `timeout` | لا رد خلال 5 ثوانٍ | «لا ردّ من الخادم — قد يكون مشغولاً أو متوقفاً» |
| `unknown` | أي رمز آخر (مثل 1006) | «سبب غير معروف» + **رمز الإغلاق** في النص |

- بعد إغلاق مجهول يُشغّل الواجهة **تحقيقاً تلقائياً** على `/health` بعد 800ms: إن فشل يُرقّى السبب إلى
  `timeout` (أو `network` لو كان المتصفح offline) ويُعاد رسم الشريط.
- الشريط `#connBanner` (أعلى `.main`) يعرض: السبب + النص العربي + «إعادة المحاولة خلال Ns» (عدّاد حيّ)
  + زر «إعادة المحاولة الآن» + رابط «تشخيص».
- إعادة اتصال تلقائية بتراجع أسّي `1s, 2s, 4s … حتى 30s` مع عرض العدّاد.
- عند العودة: صوت `reconnected` + إشعار + `bind` للمحادثة الحالية + `list_sessions` + `get_usage`
  + **إعادة عرض أي حوار موافقة معلّق** (نسخة محفوظة لحظة الانقطاع تُعاد إلى طابور `extension_ui` بعد `ready`)
  مع شريحة تنبيه «🔄 أُعيد عرض طلب موافقة معلّق».
- سجل **آخر 20 حدث اتصال** في الذاكرة (وقت، نوع الحدث، رمز الإغلاق، السبب) يُعرض في نافذة «🩺 تشخيص»
  وفي لوحة الإشعارات.
- مستمعا `online`/`offline` يعزّزان التصنيف: `offline` يعلن الانقطاع فوراً، و`online` يصفّر المحاولات ويعيد الاتصال.

## 4) لوحة الإشعارات `#notifyPanel` (زر 🔔 في الشريط العلوي)

`<dialog>` أصلي (طبقة عليا + `::backdrop`)، RTL ومتجاوب:

- المفتاح العام للأصوات.
- مستوى الصوت (0–100) مع قيمة حيّة.
- جدول أنواع الأصوات: الاسم العربي + الوصف + مفتاح تشغيل/إيقاف لكل نوع + زر «تجربة».
- حالة صلاحية إشعارات النظام + زر «إعادة الطلب» عند الحاجة (وتحذير أحمر بارز عند الرفض).
- سجل آخر 20 حدث اتصال في جدول (الوقت · الحدث · رمز الإغلاق · السبب) مع زر **«مسح السجل»**.
- إغلاق بـEsc أو بالنقر على الـ`::backdrop` أو بزر ✕.

كل الأنماط مضافة **في نهاية `styles.css`** (`C3 — تنبيهات…`) بلا تعديل أي قاعدة قائمة، وتستخدم متغيّرات
الثيمين، وتُوقف الحركات تحت `prefers-reduced-motion`.

## 6) ملاحظات
- لم يُعد تشغيل خادم الإنتاج؛ الاختبار كله على 8793 (والخادم المؤقت أُوقف بعد الاختبار).
- إن أُفرغ السجل أو أُعيد تحميل الصفحة يبدأ السجل من جديد (ذاكرة فقط، لا يُحفظ).
- بروتوكول الموافقة كما هو: نفس `extension_ui` / `extension_ui_response` / `extension_ui_dismiss`، ولم تُغيَّر أسماء الأحداث.
- خطّاف الاختبار `window.__soundBus` / `window.__test` مربوط بشرط `?soundtest=1` فقط.
