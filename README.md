# مساعد Pi — واجهة ويب عربية RTL + بوت تيليجرام

واجهة احترافية بالعربية (من اليمين إلى اليسار) لوكيل **Pi** البرمجي، إلى جانب بوت تيليجرام
بواجهة أزرار ونصوص عربية متقنة. يستطيع الوكيل قراءة الملفات، تشغيل الأوامر، تحرير الكود،
وإدارة الجلسات — مباشرةً من المتصفح أو من تيليجرام.

---

## ✨ المزايا

### واجهة الويب
- تصميم عصري **RTL** بالكامل مع دعم الوضعين الداكن والفاتح.
- بثّ مباشر للردود (streaming) مع مؤشر كتابة.
- عرض **سلسلة التفكير** (thinking) في قسم قابل للطي.
- بطاقات **استدعاء الأدوات** مع أمر/مسار الأداة وإمكانية عرض الناتج.
- عرض Markdown كامل: عناوين، قوائم، اقتباسات، جداول، وكتل كود مع زر نسخ.
- شريط جانبي للمحادثات المحفوظة، وتبديل النموذج ومستوى التفكير، وضغط السياق.
- متجاوب مع الجوال، ويحفظ إعداداتك محلياً.

### بوت تيليجرام
- رسائل منسّقة (HTML) مع تحويل Markdown إلى تنسيق تيليجرام.
- **لوحات مفاتيح تفاعلية** لاختيار النموذج والتفكير والجلسات.
- تحديث مباشر لرسالة الرد أثناء التوليد + زر إيقاف.
- أوامر: `/start` `/new` `/model` `/think` `/status` `/stop` `/compact` `/sessions` `/help`.
- دعم RTL وأرقام عربية في النصوص، وتقسيم آمن للردود الطويلة.

## 🎛️ مركز التحكم (جديد)

من زر **🎛️ مركز التحكم** في الشريط الجانبي أو أعلى الصفحة تفتح نافذة كاملة فيها:

| التبويب | ما يمكنك فعله |
|---|---|
| **نظرة عامة** | عدّادات مباشرة للمهارات والوكلاء والمزوّدين والنماذج والإضافات والمحادثات + نبض الاستهلاك. |
| **المهارات** | إنشاء/تعديل/حذف مهارة (`SKILL.md`) مع وصف يحدد متى تُستخدم، وقوالب جاهزة. |
| **الإضافات** | إنشاء/تعديل/حذف Extension من قوالب جاهزة (أمر، أداة، مراقب) أو كودك الخاص. |
| **MCP** | عرض خوادم MCP المفعّلة/المعطّلة، وتفعيلها أو تعطيلها. |
| **الوكلاء** | إنشاء وكلاء بأدوار (قائد، مخطط، منفذ، مراجع، باحث، مخصص) وتعليمات ونموذج ومستوى تفكير. |
| **المزوّدون** | إضافة مزوّد متوافق مع OpenAI/Anthropic/Google، حفظ مفتاح API، وإدارة النماذج. |
| **الاستهلاك والحدود** | ضبط الحد اليومي/الأسبوعي للتوكنز والتكلفة، ومشاهدة المتبقي ورسوم 14 يوماً. |
| **الصلاحيات** | مصفوفة تفاعلية لكل وكيل × صلاحية (قراءة، كتابة، تنفيذ، شبكة، تفويض، موافقة). |

### شريط الاستهلاك

أسفل الشريط العلوي شريط دائم يعرض:

- **اليوم**: التوكنز المستهلكة، التكلفة، والمتبقي من الحد اليومي.
- **الأسبوع**: نفس المؤشرات مع إعادة ضبط أسبوعية (تبدأ الأحد).
- **سياق الجلسة**: التوكنز المشغولة من نافذة سياق النموذج الحالي.

الحدود الافتراضية `1,000,000` توكن يومياً و`5,000,000` أسبوعياً، ويمكن تغييرها أو جعلها بلا حد من تبويب **الاستهلاك والحدود**. تُحفظ في `data/usage.json`.

### 🔗 خوادم MCP

- تُقرأ الخوادم من `~/.pi/agent/mcp.json` (وخادم المشروع من `.pi/mcp.json`).
- يدعم Pi النقل **Streamable HTTP** و stdio، ولا يدعم SSE. تم تحويل خادم x64dbg من `/sse` إلى `/mcp` بعد التحقق.
- أدوات MCP تظهر باسم `mcp__<server>__<tool>`، ولا يستطيع الوكيل استخدامها إلا إذا مُنح صلاحية **أدوات MCP**.
- الخوادم المستوردة من OpenCode مضبوطة على `exposure: "direct"` للاستخدام المباشر، مع إخفاء الأدوات التي منعها OpenCode عبر `toolExposure: "hidden"`.
- بعد تعديل `mcp.json` اضغط **«إعادة تحميل»** أو ابدأ محادثة جديدة.

### 🔗 مزامنة الويب وتيليجرام

أصبحت الواجهة وبوت تيليجرام يستخدمان **جلسة واحدة مشتركة** افتراضياً:

```env
SHARED_SESSION_ID=shared:main
SYNC_WEB_TELEGRAM=true
```

- أي طلب تكتبه في الويب يظهر في تيليجرام، والعكس.
- الردّ يتدفّق مباشرة في المكانين، مع أدوات ورسائل الحالة.
- أزرار الإيقاف، تغيير النموذج، التفكير، الجلسة الجديدة، وتبديل الجلسات تؤثر في الجلسة المشتركة.
- في الويب تظهر شارة **🔗 الويب + تيليجرام**، وتظهر رسائل تيليجرام بعلامة 📱.
- لإيقاف المزامنة: اجعل `SYNC_WEB_TELEGRAM=false` أو افرغ `SHARED_SESSION_ID`.

> ملاحظة: عند المزامنة، كل محادثات تيليجرام المسموح لها تشترك في الجلسة نفسها. إذا كنت تحتاج جلسات منفصلة لكل مستخدم، عطّل المزامنة أو شغّل نسخة أخرى من التطبيق.

### 🖥️ VMware MCP

تمت إضافة خادم MCP محلي لـ VMware Workstation:

- الملف: `scripts/vmware-mcp-server.mjs`
- مضاف إلى `~/.pi/agent/mcp.json` باسم `vmware`.
- الأدوات المتاحة:
  - `vmware_host_info` — معلومات مضيف Windows (الاسم، الطراز، اللوحة، المعالج، النظام).
  - `vmware_list_vms` — الأجهزة الافتراضية التي تعمل وكل الأجهزة.
  - `vmware_vm_info` — بيانات `.vmx` + بيانات المضيف.
  - `vmware_get_guest_ip` — IP الضيف عبر VMware Tools.
  - `vmware_check_tools` — حالة VMware Tools.
  - `vmware_list_snapshots` — اللقطات.
  - `vmware_power` — تشغيل/إيقاف/تعليق/إعادة تشغيل.
  - `vmware_capture_screen` — لقطة شاشة (تتطلب بيانات دخول).
  - `vmware_run_guest_command` — تنفيذ أمر داخل الضيف (يتطلب بيانات دخول).
  - `vmware_detect_virtualization` — بصمات من داخل الضيف: VMware، BIOS، MAC، VMware Tools، ومحاولة كشف اسم المضيف عبر بوابة NAT/NetBIOS/DNS.

#### بيانات دخول الضيف
لا تُخزَّن كلمات المرور في الكود. أضفها إلى بيئة خادم MCP في `mcp.json` (الملف بصلاحيات 600):

```json
"vmware": {
  "command": "/home/asus/.local/share/pi-node/current/bin/node",
  "args": ["/home/asus/pi-webui-telegram/scripts/vmware-mcp-server.mjs"],
  "exposure": "direct",
  "env": {
    "VMWARE_GUEST_USER": "اسم المستخدم",
    "VMWARE_GUEST_PASSWORD": "كلمة المرور"
  }
}
```

بعد التعديل أعد تحميل الجلسة. يمكن أيضاً تمرير `user`/`password` لكل استدعاء، لكن ذلك قد يظهر في سجل المحادثة؛ يفضّل `env`.

> **ملاحظة:** من جهة المضيف يمكن دائماً معرفة اسم المضيف ونظامه. من داخل الضيف، يمكن إثبات أنه VMware واستخراج بصمات العتاد الافتراضي، لكن اسم الجهاز المضيف الفيزيائي ليس مضموناً إلا إذا كشفته VMware Tools أو الشبكة (بوابة NAT/NetBIOS/DNS) أو مجلدات مشتركة.

### توزيع الصلاحيات والتفويض

- كل وكيل له صلاحيات تُترجم فعلياً إلى أدوات مسموحة عند إنشاء الجلسة:
  - القراءة → `read, grep, find, ls`
  - الكتابة → `write, edit`
  - التنفيذ → `bash`
  - الشبكة → `web_search, web_fetch`
  - التفويض → أداة `delegate`
- وكيل **القائد** يملك أداة `delegate` التي تنشئ جلسة فرعية معزولة للوكيل المطلوب وتعيد نتيجته.
- تعديل صلاحيات وكيل قائم يُطبّق عند إنشاء الجلسة التالية، أو فوراً بعد زر **«إعادة تحميل»**.
- ملفات الوكلاء: `data/agents.json` (تُنشأ تلقائياً بستة أدوار جاهزة).

> **مهم:** بعد إضافة مهارة أو إضافة جديدة، اضغط **«إعادة تحميل»** في مركز التحكم لتطبيقها على الجلسة الحالية، أو ابدأ محادثة جديدة.

## 🎛️ إدارة الخادم (تشغيل/إيقاف/إعادة تشغيل)

استخدم السكربت `server.sh`:

```bash
./server.sh start          # تشغيل في الخلفية
./server.sh stop           # إيقاف
./server.sh restart        # إعادة تشغيل
./server.sh status         # الحالة + فحص الصحة
./server.sh logs           # متابعة السجل
./server.sh run            # تشغيل في المقدمة (للتطوير)
./server.sh start --no-telegram   # ويب فقط
```

- يعمل الخادم تحت **مشرف تلقائي** يعيد تشغيله عند الانهيار.
- **إعادة التشغيل من الواجهة أو تيليجرام** متاحة عندما يكون الخادم مُداراً عبر `server.sh start`:
  - الويب: زر ♻️ في الشريط الجانبي.
  - تيليجرام: `/restart` أو زر «إعادة التشغيل» مع تأكيد.
- **إعادة تشغيل آمنة من داخل الوكيل:** إذا نفّذ الوكيل `./server.sh restart` أثناء مهمة،
  فلا يُقطع التشغيل؛ يُكتب طلب إعادة تشغيل وينتظر الخادم انتهاء المهمة ثم يعيد التشغيل تلقائياً.
  هذا يمنع بقاء الجلسات معلّقة أو توقف الخادم نهائياً.
- الملفات: `.run/server.pid` و`.run/server.log` (ويُحفظ السابق في `server.log.prev`).
- في الإنتاج يُفضّل استخدام systemd (انظر أدناه).

> ملاحظة: **بدء** الخادم لا يمكن أن يكون من الواجهة أو تيليجرام لأنهما متوقفان أصلاً؛
> البدء يكون عبر `./server.sh start` أو systemd. الإيقاف من الواجهة غير متاح عمداً،
> أما إعادة التشغيل فمتاحة.

### إعادة التشغيل بعد التحديث

بعد تعديل الكود أو الإعدادات أعد تشغيل الخدمة:

```bash
./restart.sh
```

يكتب السجل في `data/server.log` ومعرّف العملية في `data/server.pid`.

## 🤖 إعداد بوت تيليجرام

1. افتح محادثة مع [@BotFather](https://t.me/BotFather) في تيليجرام.
2. أرسل `/newbot` واتبع التعليمات للحصول على **التوكن**.
3. ضع التوكن في `.env`:

```env
TELEGRAM_BOT_TOKEN=123456:ABC-DEF...
```

4. (اختياري) لتقييد البوت بك، أرسل رسالة للبوت ثم افتح
   `https://api.telegram.org/bot<TOKEN>/getUpdates` وخذ `message.from.id` وضعه في:

```env
TELEGRAM_ALLOWED_USERS=123456789
```

5. أعد التشغيل، ثم أرسل `/start` للبوت.

## 🧠 كيف يعمل

يستخدم المشروع **Pi SDK** داخل العملية نفسها:

- `ModelRuntime` لتحميل النماذج المتاحة والمصادقة.
- `createAgentSession` لكل محادثة، مع `DefaultResourceLoader` لاكتشاف الأدوات والإضافات.
- الاشتراك في أحداث الجلسة (`text_delta`, `tool_execution_start/end`, `agent_settled`…)
  وتوحيدها ثم بثّها إلى الويب وتحديث رسائل تيليجرام.

تُحفظ كل محادثة في جلسة Pi مستقلة تحت `data/sessions/`، وتُعاد فتحها عند الطلب.

## 🧰 خدمة systemd (اختياري)

`/etc/systemd/system/pi-webui.service`:

```ini
[Unit]
Description=Pi Arabic Web UI + Telegram
After=network-online.target

[Service]
Type=simple
User=asus
WorkingDirectory=/home/asus/pi-webui-telegram
Environment=PI_SUPERVISED=1
ExecStart=/home/asus/.local/share/pi-node/current/bin/node src/index.js
Restart=on-failure
```

## 🛠️ استكشاف الأخطاء

| المشكلة | الحل |
|---|---|
| `تعذّر العثور على حزمة Pi` | شغّل `npm run setup` أو اضبط `PI_MANAGED_INSTALL_ROOT`. |
| `لا يوجد نموذج متاح` | تأكد من `auth.json` أو مفاتيح API في البيئة. |
| خطأ `no credits` | مفتاح OpenAI بلا رصيد؛ اختر مزوّداً آخر من `.env` أو الواجهة. |
| البوت لا يرد | تحقق من `TELEGRAM_BOT_TOKEN` ومن أن البوت غير مستخدم في webhook آخر. |
| الواجهة "غير متصل" | تأكد من المنفذ و`WEB_TOKEN` في رابط الفتح، ومن أن الخادم يعمل: `./server.sh status`. |
| جلسة توقفت وسط أداة بعد إعادة تشغيل | أصلحها بـ: `node scripts/repair-session.mjs <session.jsonl>` ثم أعد التشغيل. |
| مهمة `delegate` تطول بلا أخبار | لها مهلة `DELEGATE_TIMEOUT_MS` (5 دقائق افتراضياً) وتُظهر تقدّماً كل 15 ثانية؛ يمكن تعطيلها بـ `DELEGATE_ENABLED=false`. |
| سجل الواجهة يظهر فارغاً | يُعاد تحميل السجل تلقائياً بعد لحظة؛ إن استمر، أعد تحميل الصفحة. |

## English summary

An Arabic-first (RTL) web UI plus a polished Telegram bot for the Pi coding agent.
Run `npm run setup`, edit `.env`, then `npm start`. The web UI streams responses,
shows tool calls and reasoning, and manages sessions; the Telegram bot offers inline
keyboards, formatted RTL text, live streaming edits, and the usual commands.
